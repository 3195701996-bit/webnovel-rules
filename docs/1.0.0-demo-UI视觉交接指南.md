# 1.0.0-demo UI / 视觉 / 交互交接指南

**交接版本：** `versionCode 114` / `versionName 1.0.0-demo`  
**代码基线：** `60bdc97`  
**产品定位：** 升级版 Venera：漫画优先、内置源、手机独立运行，同时保留小说阅读能力。  
**交接目标：** 功能侧已接近完成；本阶段由 UI 团队优化视觉体系、信息层级、按钮布局、操作反馈与移动端阅读体验。本文约束“可自由设计的范围”和“不能破坏的功能契约”。

> **核心原则：界面可重做，行为不可猜改。** UI 团队可以更改 Compose 布局、主题、色彩、字号、组件分层、图标、动效、空/加载/错误状态与按钮位置；任何会改变网络请求、路由参数、数据写入、任务控制、缓存清理、阅读恢复或安全限制的改动，必须转交功能负责人审查。

---

## 1. 当前应用形态

```text
Android 原生 Compose UI
    ↓ 仅应用内部调用
EngineGateway（127.0.0.1 + 会话 Token）
    ↓
内嵌 CPython / 本机服务 / 私有应用数据目录
    ↓
内置书源、已下载小说与漫画、任务、阅读进度
```

- 应用不依赖电脑或云端后端；联网仅用于搜索、详情、在线正文和图片下载。
- 应用数据、书源、进度与下载内容都在 Android 私有目录；视觉改造不得改为外部路径、共享目录或桌面数据。
- 首次启动需要本机引擎解包，可能有明显等待时间。该状态必须保留，不得用静态假成功页替代。
- 引擎不可用时，已下载内容仍可通过离线书架打开；视觉改造必须保留“重试 / 返回书架 / 诊断”的降级路线。

## 2. 页面地图与视觉优先级

### 一级导航

| 页签 | 当前职责 | 视觉目标 | 不可破坏行为 |
|---|---|---|---|
| 书架 | 展示小说、漫画、继续阅读、离线内容 | 作为首页，突出最近阅读、封面、进度、新话和离线状态 | 点击条目必须进入对应详情或离线阅读；不能丢失阅读进度标识 |
| 浏览 | 漫画优先的发现、内置源、小说搜索 | 形成清晰的“搜漫画 / 浏览源 / 搜小说”分流 | 漫画搜索、单源搜索、浏览分类必须维持原生目的地和已有筛选状态 |
| 下载 | 队列、暂停、继续、停止原因、检查更新 | 突出任务状态、恢复点和可操作性 | 不能隐藏停止原因、断点标签、继续/删除操作；高风险动作保留确认流程 |
| 设置 | 阅读偏好、网络、书源、存储、备份、诊断 | 用分组和风险层级降低复杂度 | 代理、清理、恢复、书源管理和诊断必须可达，说明文字不能被删除 |

### 关键覆盖页面

| 页面 | 可优化重点 | 功能契约 |
|---|---|---|
| 空书架 | 首用引导、内容类型分流、插画/空态 | 三个原生入口必须保留：搜漫画、浏览内置漫画源、搜小说；不得回退到网页首页 |
| 漫画详情 | 封面、元数据、章节分组、下载选择、阅读入口 | “开始/继续阅读”、准确的下载状态、按话选择、更新检查、移除行为必须保留 |
| 漫画阅读器 | 沉浸阅读、顶部/底部控制、目录、缩放、翻页/连续模式 | 页码、章节身份、阅读进度保存、目录切换、缩放和离线图片路径不可改写 |
| 小说详情与阅读器 | 字体、行距、主题、目录、加载/未下载态 | 正文状态不可伪造；未下载章节仍须显示明确的手动获取入口 |
| 漫画源页 | 源健康、类别、验证状态、单源搜索 | 源可用性、降级/未验证状态不能被仅用颜色掩盖；“在此源搜索”必须保持该源过滤 |
| 书源管理 | 批量启停、导入、校验、恢复 | SSRF 提示、校验范围、导入/删除/恢复确认不能移除 |
| 存储管理 | 占用、可再生缓存、回收站、按书清理 | 删除、清理、回收站属于高风险动作；不能取消确认框或模糊数据范围 |
| 备份与恢复 | 文件选择、范围说明、校验和 | 必须继续说明备份不包含正文与漫画图片；不许承诺“完整内容备份” |
| 网络/代理 | 可选网络出口 | 保持“默认直连、代理可选、不改系统代理”的事实；不得把代理包装为必填或云服务 |
| 引擎加载/失败 | 启动、重试、离线降级、诊断 | 不得去掉阶段、错误、重试、返回书架和产物信息 |

## 3. 允许修改的内容

### 3.1 视觉系统

可以建立完整的 `MaterialTheme` / 设计 Token：

- 亮色、深色和阅读器夜间主题；
- 主/辅色、危险色、成功色、离线色、未验证色的语义 Token；
- 字体层级、行高、圆角、阴影、分割线、封面比例与卡片密度；
- 图标替换（优先 Material Icons 或项目已使用的资源）；
- 骨架屏、淡入、列表分批出现、状态转场等低干扰动效；
- 紧凑/舒适两种列表密度，以及平板横屏的双栏/三栏布局。

不要继续在新 UI 中散落 `Color(0x...)`、固定字体尺寸或硬编码间距。统一 Token 后，现有状态色必须映射到语义，而不是被统一成“好看但不可区分”的颜色。

### 3.2 交互与信息架构

允许：

- 调整顶部栏、底部栏、浮动操作按钮、按钮组及卡片操作的摆放；
- 将低频设置折叠到二级页面；
- 为高频入口增加明确的主要操作，例如“继续阅读”“搜索漫画”“下载选中”；
- 将冗长说明收进“了解详情”，但保留风险结论、错误原因和可恢复性提示；
- 用 Chip、Badge、进度条和状态卡提升源、下载和阅读状态可读性；
- 支持横竖屏、系统字体放大、深色模式与窄屏设备。

### 3.3 可访问性与移动适配

- 所有可点击目标应满足至少 `48dp × 48dp` 的触控范围；Android Compose 的 Material 组件也遵循这一可访问性方向。[Android Compose 触控目标说明](https://developer.android.com/develop/ui/compose/modifiers-list)
- 所有无文字图标必须有内容描述；封面图片应保留作品标题描述。
- 颜色不能是唯一状态来源：下载失败、源降级、未验证、离线、危险删除还需要文字或图标。
- 不要用固定屏幕高度定位按钮；键盘弹出、系统字体放大和横屏时仍应可滚动、可返回。
- 阅读器页面避免影响图片原始比例和小说正文可读性；不得为了“齐整”裁切长图。

## 4. 禁止改动：功能与数据契约

### 4.1 路由与状态

不得修改或绕过：

- `Dest` 路由类型与 `destKey` 的稳定键策略；返回详情、搜索、分类页时要恢复查询词、筛选、页码和滚动位置。
- 漫画阅读的 `source`、`comicId`、章节身份、`startChapterId`、`startLabel`、`trusted` 与 `note` 语义。
- 继续阅读的身份恢复逻辑：不允许用视觉层参数强制跳到第一章/第一话，或用自动保存覆盖“不精确定位”的历史。
- 引擎加载、失败、离线降级、重试与诊断状态机。
- `EngineGateway`、本机端口、会话 Token、HTTP 路径、Cookie 安装和网络安全设置。

### 4.2 高风险写操作

以下动作不得被做成无确认、无状态或无错误反馈的普通图标按钮：

- 删除下载任务、停止任务、清空回收站；
- 删除书架记录或连同文件删除；
- 清理可再生缓存、漫画缓存、失败章节缓存；
- 从备份恢复；
- 导入、覆盖、删除书源；
- 设置或清除代理；
- 重建漫画图片缓存。

UI 可改确认框版式和措辞，但必须表达：**会影响什么、是否可恢复、执行中状态、成功/失败结果**。

### 4.3 WebView 边界

核心流程的书架、浏览、搜索、详情、阅读和普通下载控制均应保持 Compose 原生页面。

当前仅有两类受控 WebView 例外：

1. 设置中的“网页诊断”；
2. 下载页中的“选择章节下载（完整网页界面）”及小说任务/导出完整操作。

视觉团队不得将这些例外放回一级导航、首用入口或搜索入口；也不得删除 Cookie 等待、仅回环访问、禁止文件访问、禁止混合内容、外链交给系统浏览器和 SSL 错误取消等安全限制。

## 5. 测试标签与自动化兼容性

`Modifier.testTag(...)` 是功能验收的稳定选择器，不是视觉样式。**重构布局时必须原样保留标签、含义和触发动作**；如必须更名，先同步更新对应测试并由功能负责人复核。

重点标签包括：

```text
empty_shelf_search_manga      empty_shelf_browse_manga
empty_shelf_search_novel      manga_search_field
manga_source_list             manga_source_page
manga_search_in_source        manga_pager
manga_pages                   manga_resume_note
pick_<chapterId>              download_selected
check_update                  downloads_list
check_library_update          task_resume
storage_list                  clear_regen
clear_manga_cache             storage_confirm
proxy_entry                   build_info
export_diagnostics            history_list
prefs_font
```

高价值验收路径已有 Android 仪器化用例：

- `FirstRunNativePathTest.kt`：空书架 → 原生漫画搜索 / 原生源浏览，不出现桌面网页；
- `MangaUiAcceptanceTest.kt`：书架 → 详情 → 原生漫画阅读 → 缩放 / 翻页 / 进度；
- `ReaderUiAcceptanceTest.kt`：书架 → 小说详情 → 原生阅读 → 目录 / 偏好 / 进度；
- `SettingsScreensUiTest.kt`：书源、备份、诊断、任务恢复与阅读偏好入口；
- `DownloadResilienceTest.kt`、`OfflineModeTest.kt`、`NetworkLossTest.kt`、`ForceStopResilienceTest.kt`：下载、离线、断网与恢复边界。

UI 改造完成后，至少执行上述覆盖页面的仪器化用例；不要只做截图比较。

## 6. 建议的 UI 交付节奏

### 阶段 U1：建立设计系统，不改行为

- 提取颜色、字体、间距、圆角和状态 Token；
- 统一一级导航、顶部栏、卡片、Chip、按钮、加载/空/错误状态；
- 先改书架、浏览、下载、设置四个一级页签；
- 不调整路由、不改 API、不删 `testTag`。

**验收：** 可编译；冷启动、四页切换、返回栈、引擎失败和离线书架均可用。

### 阶段 U2：阅读与详情体验

- 漫画详情、章节目录、下载选择、阅读器控制栏；
- 小说详情、正文排版、目录、阅读偏好；
- 重点处理单手操作、长标题、超长章节列表、图片加载和大字号。

**验收：** 漫画与小说的完整自检闭环通过；阅读进度、图片比例、目录、下载状态不回归。

### 阶段 U3：设置与风险操作

- 书源、存储、备份、网络、诊断的分组和风险层级；
- 把高风险操作做成清晰确认流程；
- 优化错误提示、任务恢复、源验证与诊断报告入口。

**验收：** 备份范围、清理确认、代理可选、任务停止原因、离线说明均仍可见且可操作。

## 7. UI 验收清单

### 功能不回归

- [ ] 冷启动不显示调试控制台；空书架三入口均原生。
- [ ] 书架、浏览、下载、设置四页签可切换，覆盖页返回后状态不丢失。
- [ ] 漫画/小说继续阅读恢复正确章节和页码。
- [ ] 漫画长图比例正确；连续模式、翻页模式、缩放和复位可用。
- [ ] 小说未下载章节不伪造正文；提供明确的在线获取入口。
- [ ] 单源漫画搜索仍保留源过滤，搜索错误不淹没结果。
- [ ] 下载暂停、继续、删除、停止原因、检查更新仍可用。
- [ ] 离线时已下载内容可阅读；搜索和下载入口如实说明需要引擎/网络。
- [ ] 书源、存储、备份、代理等高风险动作仍有说明、确认和结果反馈。
- [ ] 网页诊断与完整下载网页没有进入核心导航或首用路径。

### 视觉与体验

- [ ] 深色/亮色/阅读夜间主题对比足够，状态不只靠颜色区分。
- [ ] 点击目标满足最小触控尺寸；无文字图标有内容描述。
- [ ] 手机窄屏、大字号、横屏和键盘弹出时，操作不被遮挡。
- [ ] 长书名、长章节名、无封面、加载中、空数据、部分源失败、断网、低存储等状态不溢出、不重叠、不误导。
- [ ] 动效可被系统“减少动态效果”偏好抑制，且不阻塞操作。

## 8. UI 提交与发布规则

1. 一个 UI 提交只处理一个清晰主题，避免和书源、缓存、代理或爬虫修复混合。
2. 不提交 `sources/`、`data/`、缓存、日志、下载内容、代理状态或真实诊断报告。
3. 任何新增依赖、权限、WebView 配置、文件访问、网络请求或后台行为均需功能负责人先审查。
4. 产物版本、`versionCode`、Git revision、构建时间、签名和 APK SHA-256 必须属于同一 APK。
5. `1.0.0-demo` 是功能交接基线，不代表正式稳定版；UI 完成后需重新构建、跑回归、真机验收，再决定后续版本号。
