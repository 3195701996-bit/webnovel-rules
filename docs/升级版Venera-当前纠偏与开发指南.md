# 升级版 Venera：当前纠偏与开发指南

**更新日期：2026-09-16**  
**适用范围：** `webnovel_rules` 的 Android 独立阅读器、内嵌 Python 引擎及移动端漫画/小说能力。  
**产品定位：** 开发升级版 Venera，不是把桌面网页或桌面爬虫控制台装进 APK。

> 本文是当前执行基线，不是发布成功声明。源码提交、离线测试和设备测试只能证明各自覆盖的范围；用户目标机、用户网络和真实源站的完整闭环必须单独记录。

## 1. 当前项目结构

```text
webnovel_rules/
├── android/                         # Android Gradle 工程
│   └── app/src/main/
│       ├── java/com/webnovel/mobile/ # Compose UI、回环网关、前台服务、存储/备份
│       └── AndroidManifest.xml       # 权限、服务、网络安全配置
├── app.py                           # Flask 应用与蓝图装配
├── server/                          # HTTP API、移动入口、状态、能力/源目录、存储
│   ├── mobile_entry.py              # Chaquopy 内嵌运行入口
│   ├── manga_api.py                 # 漫画搜索、阅读、图片、下载与修复 API
│   ├── manga_catalog.py             # 移动漫画源目录与实测分类
│   ├── capabilities.py              # 运行依赖判定，不替代功能验证
│   └── novel_catalog.py             # 小说源移动可用性目录
├── engine/
│   ├── manga/                       # 漫画适配器、下载器、图片处理、验证记录
│   ├── adapters/                    # 小说专属适配器
│   └── crawler.py                   # 规则书源抓取主链路
├── sources/                         # 用户/桌面书源数据；不是 Android 代码生成物
├── data/                            # 运行数据；不是代码改动目标
├── tests/                           # Python 离线契约与回归测试
├── docs/                            # 产品、源和验收文档
└── requirements-*.txt               # 桌面/移动/开发依赖分层
```

当前 Android `build.gradle` 的产品基线是 `versionCode 77`、`versionName 0.74.1-copy-web-fast`（**以 build.gradle 为唯一事实来源**；本文写于 0.60 阶段，版本号若与 build.gradle 不一致，按 build.gradle 与《当前版本纠偏与开发执行指南》为准）。构建时 Python 源码经过白名单快照进入 APK；不得手动改 `build/`、APK 解包文件、`data/`、用户书源或桌面虚拟环境来“修复移动端”。

### 模块责任边界

| 层 | 负责什么 | 不应负责什么 |
|---|---|---|
| Compose UI | 书架、搜索、源状态、详情、阅读、下载、存储、诊断和设置 | 渲染桌面 HTML 或承担图片解混淆 |
| `EngineGateway` / 回环 HTTP | 原生 UI 到 Python 的受控本机契约、会话和错误映射 | 暴露局域网/公网服务 |
| Python `server/` | API、源目录、运行状态、缓存和事务 | 把依赖探测冒充真实源站验证 |
| `engine/manga/` | 适配器、图片请求、源特定处理、缓存写入、下载调度 | 让 Android UI 猜测源的防盗链/还原规则 |
| `engine/adapters/` / 规则引擎 | 小说搜索、目录、正文 | 改动移动 UI 路由 |
| 测试 | 锁定离线算法/API/设备交互契约 | 宣称所有用户网络和外站均已通过 |

## 2. 已完成的方向纠偏

### 2.1 核心阅读流不再默认进入网页

搜索、漫画详情、阅读、下载、漫画源管理、小说源管理和存储管理已有 Compose 页面。WebView 仅允许保留为**显式网页诊断入口**，不得作为以下行为的默认或兜底路径：

- 空书架后的第一次搜索；
- 漫画搜索、单源搜索、详情、目录和阅读；
- 下载、书源管理或阅读历史；
- 用“改 localhost 地址”解决本机服务状态。

任何新增 `Dest.Web`、`WebView`、`loadUrl` 或 JavaScript 桥接，必须在评审中说明为什么原生 API/页面无法完成该任务，并且不能放在用户核心流程上。

### 2.2 分源漫画搜索已接入原生契约

服务端漫画搜索支持 `source` 和 `order`。移动端后续改动必须保持：

1. 全部源、单源、排序、首搜、流式搜索、阻塞回退和翻页使用同一份参数状态。
2. 源详情的“在此源搜索”必须携带该源 key，而不是打开不带过滤条件的通用搜索。
3. 换源时清掉前一个源的结果；仅因页面返回/重建不得丢失当前源、关键词、页码、排序和滚动位置。
4. `unsupported` 源不发起搜索；`degraded` 源允许明确选择并显示风险；`pending` 不能标注为可用。

### 2.3 图片错误缓存已开始自愈

0.51.0 的 JM 图片块错乱来自旧的固定扩展名截断逻辑。当前图片管线已使用处理版本：

- `jm.py` 的 `PROCESS_VERSION=2` 表明修复后的处理算法版本。
- `_processed.json` 记录每个章节和源的处理版本。
- 下载器在读缓存前检查处理版本；混淆源的旧版本缓存会整章清理后重新取得，避免先写一页新图就把其它旧花图误认为当前版本。
- HTTP 本地图片直出也检查处理版本；有适配器时旧缓存不再直接返回。
- 源已移除、无法取得适配器时，仍保留已有本地阅读能力，避免因源状态变化锁死用户已经下载的内容。

这项机制只清理受影响章节的图片与处理标记，**不清书架、收藏、阅读历史、下载任务记录或小说数据**。

### 2.4 移动漫画源目录已经成为能力展示入口

`server/manga_catalog.py` 汇总四类事实：

- 实际已注册的适配器；
- 依赖探测结果；
- 已落盘的逐源功能验证；
- 仓库中存在但未注册的适配器及保留原因。

用户界面必须始终将以下三件事分开显示：

1. **依赖判定：** 代码运行时是否具备依赖；
2. **实测结论：** 搜索、详情、取图是否真实成功；
3. **移动可用性：** `Android 已验证`、`Android 降级`、`Android 不支持`、`待验证`、`已弃用/未注册`。

依赖满足并不等于外站可用。反过来，源站网络失败也不能被误报为 APK 不支持。

## 3. 本轮已执行的代码纠偏

本轮仅改动移动图片缓存和能力台账的代码与测试；未修改 `sources/`、`data/`、桌面运行服务或外站请求策略。

### 3.1 修复旧处理版本图片仍被读取

新增章节处理版本读取、当前版本判断和旧版本整章失效逻辑。核心原则：

- 无图片后处理的源不受版本标记限制；
- 有处理版本的源，目录标记缺失、损坏或版本不匹配时不能直接返回图片；
- 在下载新页之前清整章旧版本图片，避免“当前页新、其它页旧”的混合章节；
- 如果源已经不可用，保留本地直出能力，不因版本检查阻止用户查看已下载内容。

新增离线回归：旧标记版本加两张合法图片时，下一次取图会重建当前页、移除同章旧页，并更新为当前处理版本。

### 3.2 补齐 `baozi` 的能力台账

`baozi` 已在漫画注册表中出现，但原能力台账未声明其 `lxml` 解析依赖及图片传输降级能力，导致它被误标为“未登记”。现已补为：

- API 依赖：`lxml`；
- 图片增强依赖：`curl_cffi`；
- 缺少 `curl_cffi` 时显示 `degraded`，而不是伪称完整能力；
- 即使依赖满足，未通过真实搜索/详情/取图验证时仍保持 `pending`，不显示“Android 已验证”。

### 3.3 移除无效的硬图片依赖分支

下载器只有 `image_soft` 的 requests 降级路径，能力台账中不存在 `image` 硬依赖定义。已移除永远无法命中的硬图片分支，避免维护者误以为该状态会被正确输出。

## 4. 当前未闭环项：必须继续矫正

### P0：目标手机的真实漫画闭环

截至本文更新，离线与设备测试不能替代“用户手机 + 用户网络 + 真实章节”的验证。每个准备对用户显示为可用的漫画源，都必须完成：

```text
原生单源搜索
  → 详情/目录
  → 第一张图
  → 多页连续阅读
  → 下载一话
  → 断网打开已下载章节
  → 关闭/重启引擎后恢复阅读
```

记录源 key、APK SHA-256、应用版本、设备 Android 版本、网络类型、失败阶段、受控错误码和测试时间。不得记录账号凭据、Cookie、完整签名参数或个人信息。

### P0：旧缓存升级体验

本轮代码会在重新访问受影响章节时失效旧图，但不应把自动失效误说成“已经替所有用户完成修复”。发布说明必须：

- 说明旧 JM 花图会在下一次联网打开该章节时重新取得；
- 提供源页面的“重建图片缓存”作为主动修复入口；
- 明确重建范围只删除图片缓存；
- 在无网络时显示“旧图片需要重新获取”，不显示为新的图片解码错误。

### P0：移动源清单收敛

桌面适配器和移动适配器不是同一承诺。下列能力不得被加入“Android 已验证”：

- 依赖 Playwright/桌面 Chrome 的网页渲染通道；
- 依赖 `curl_cffi` TLS 指纹、但 APK 未携带可用实现的 API 通道；
- 未注册、仅有源码文件的适配器；
- 只通过依赖探测、没有真实三阶段结果的源。

不能通过删除源来提高通过率。未注册或暂不支持的源应保留在开发台账，向用户解释原因，不进入默认可用列表。

### P1：小说回归与正文质量

小说侧已有移动可用性目录、最小回归源集、缓存/进度自愈和正文净化，但用户曾报告仅部分小说源可用。因此每次修改抓取、缓存、网络判断、移动快照或正文净化时，必须运行具名小说最小回归集。失败时显示源/阶段/时间，不能用“网络异常”覆盖全部细节。

### P1：后台与数据生命周期

Android 前台服务只能让任务在系统允许的范围内继续，不能承诺永久保活。下载、校验和缓存重建必须：

- 有可见的暂停、取消、超时和系统终止原因；
- 记录可恢复检查点；
- 由用户重新打开或明确继续，而不是以隐式重启规避系统限制；
- 在应用私有目录保存运行数据，导入/导出走 SAF；
- 备份范围明确区分“配置/书架/历史”与“可能体积很大的正文/图片”。

## 5. 停止项

以下做法与升级版 Venera 目标冲突，后续不再作为修复路线：

| 停止项 | 原因 | 替代方式 |
|---|---|---|
| 把桌面 HTML/网页搜索塞进 WebView | 只是在原生壳内保留套壳主链路 | Compose 页面调用明确的本机 API |
| 将 Playwright 或桌面 Chrome 作为 Android 承诺能力 | Android APK 中无等价桌面浏览器运行环境 | 标为 Android 不支持；仅保留合规的 HTTP/已验证适配器 |
| 用同名 `curl_cffi` shim 冒充依赖 | 会让能力台账错误，且难以诊断源失败 | 明确 requests 降级或不支持 |
| 以服务 `ready`、HTTP 200 或构建成功宣布源可用 | 不覆盖外站搜索、目录、图片和离线阅读 | 按逐源四阶段闭环记录 |
| 为修花图清应用数据/清所有书库 | 会损坏用户已下载内容和阅读状态 | 版本化、按源/作品/章节选择性清图片 |
| 默认切换云端/电脑后端 | 改变已确定的独立手机产品模型 | 维持本机引擎；仅在用户未来主动变更产品模型时再决策 |
| 绕过网站技术保护、规避访问限制 | 合规和稳定性风险不可控 | 遵守公开接口、条款和限速；不支持的源如实标注 |

## 6. 后续开发顺序

### 里程碑 A：修复包可安全验证

**目标：** 不再让旧算法花图或错误源状态影响新测试。

1. 合并当前图片缓存版本纠偏与 `baozi` 台账补齐。
2. 运行图片处理、能力台账、漫画目录、分源搜索和单飞的离线回归。
3. 构建带 Git revision、构建时间和签名的 release APK。
4. 记录 APK SHA-256；不要覆盖之前用户安装包。

**退出条件：** 算法/缓存/能力测试通过，静态检查无误，发布包身份可追溯。此时仍不能称“目标机漫画已验证”。

### 里程碑 B：漫画源逐源验证

**目标：** 至少形成一组真实、可复现的 Android 已验证漫画源。

1. 先从依赖不依赖桌面浏览器的源开始。
2. 每个源按 P0 四阶段链路执行并落盘结果。
3. 失败源记录失败阶段，进入 `pending` 或 `android_degraded`；不强行重试或静默换源。
4. JM 单独执行新图、旧缓存主动重建和离线读取检查。

**退出条件：** 用户可在目标手机从原生界面完成一个真实源的搜索、阅读、下载和离线打开；其他源不被高报。

### 里程碑 C：小说稳定集与数据体验

**目标：** 保住已可用小说源，同时让用户理解不可用原因。

1. 固定最小小说源回归集。
2. 验证搜索、目录、正文、进度、净化和缓存自愈。
3. 验证备份、恢复、SAF 导入导出和选择性清理不损坏书架与历史。

### 里程碑 D：升级版 Venera 体验

**目标：** 在基础可用后完善产品，而不是提前堆功能。

1. 统一漫画/小说书架、继续阅读、历史和下载状态。
2. 完善详情页、章节分组、阅读模式、图片预加载和可解释错误。
3. 将用户确认的升级功能写成独立需求与验收用例；没有确认的候选能力不应自行扩张范围。

## 7. 发布门槛

发布候选 APK 必须同时满足：

- [ ] release 签名、版本、Git revision、构建时间、APK SHA-256 可展示和记录；
- [ ] Python 快照只含白名单移动代码，不含桌面数据、虚拟环境、密钥或测试夹具；
- [ ] 离线算法/API 回归通过；
- [ ] 关键 Compose 路径 instrumentation 通过；
- [ ] 没有默认 WebView 核心流；
- [ ] 漫画源目录显示依赖、实测和移动可用性，未验证源不高报；
- [ ] JM 新图、旧版本缓存重建、下载和离线读取完成目标机验证；
- [ ] 章节 URL 的“完全本地”短路也纳入处理版本判定，旧缓存离线打开时要给出“需要重新获取”而非被当作完整章节；
- [ ] 分源搜索的首搜、流式、回退和翻页保持 source/order；
- [ ] 小说最小回归源集不退化；
- [ ] 取消、后台中断、存储不足和网络失败均显示可行动原因；
- [ ] 用户书架、历史、来源配置和下载元数据经升级/选择性重建后仍保留；
- [ ] 测试报告明确设备、网络、源、时间与失败边界，未把外站临时失败写成代码已修复。

## 8. 本轮验证记录

本轮没有访问漫画/小说外站、没有启动现有服务、没有清理任何用户数据。定向离线测试执行：

```text
pytest -q \
  tests/test_jm_unscramble_params.py \
  tests/test_jm_unscramble_ingest.py \
  tests/test_capabilities.py \
  tests/test_manga_catalog.py \
  tests/test_manga_img_flight.py
```

结果：**46 项通过**。

它证明了本轮图片处理版本、旧缓存失效、能力台账和同图单飞相关的离线契约；不证明真实 JM 章节、所有漫画源、所有小说源或用户手机网络均已通过。
