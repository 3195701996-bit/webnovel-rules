# 下一版本：可靠更新与日常阅读体验

本轮目标同时覆盖 Android、Web 和公共引擎。用户要求探索新功能并发布新版本；不能以几个后端测试通过代替整个目标完成，也不能未经实测宣称全面超过竞品。

## 必修问题

- 本地删除：完整下载、部分下载均可一键全选／取消全选；只选本地内容；保留删除确认；不影响收藏和阅读历史。
- 强制更新：绕过章节短缓存，源站新增第 42 话时能发现，不把列表第 42 项误当成第 42 话。
- 增量下载：旧目录缺少所选 ID 时刷新；全部或部分选中 ID 失配时不得回退全量，也不得报告成功。
- 重复章节：查明截图中两个第 41 话的真实身份及内容来源；不得只按标题删除、合并或隐藏；不自动删除用户数据。
- 保留整卷优先、实际已读集合、离线只读本地、在线混合阅读等既有约定。

## 探索开发与系统检查

- 更新预览：区分源站新增、本地未下载和下载不完整；下载前能确认实际章节清单，而非把所有缺失都叫新话。
- 本地管理：统一两端批量选择、选择计数、确认与完成反馈；评估可恢复删除，未实现前不承诺撤销能力。
- 下载恢复：验证暂停续传、失败页精准补齐、目录更新时的任务合并及重复点击幂等性。
- 阅读体验：验证显式章节跳转、续读、进度条、中间小区域呼出控件、长目录性能与断网续读。
- 发现体验：验证搜索滚动空间、分类筛选排序和返回位置；检查空态、错误提示及重试恢复。
- 对照已有 Venera 研究与当前实现逐项记录差距；历史研究不作为当前竞品能力的实时证据。

## 发布门槛

- 每项实施功能均有覆盖真实契约的测试，未实施的探索候选不能写成已交付。
- 后端、Web 回归、客户端契约、HTTP 冒烟及 Android 构建与单元测试通过。
- UI 交互需实际渲染验证；不能用源码字符串断言替代全选操作验收。
- 使用隔离测试数据验证新增章节增量下载与重复点击，保留旧图片、收藏和阅读记录。
- 发布包版本、签名、干净源码身份、正式下载资产一致；云端检查通过。
- App 与 Web 同步更新；关闭本轮测试工具，保留用户日常服务。
