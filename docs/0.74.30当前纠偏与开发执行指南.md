## 1. 当前项目结构与责任边界

```text
webnovel_rules/
├── app.py                         # 桌面 Flask 装配、页面路由、鉴权和后台生命周期
├── server/
│   ├── novel_api.py               # 小说搜索、书库、进度、恢复、正文维护 API
│   ├── manga_api.py               # 漫画搜索、详情、图片、下载、历史 API
│   ├── net_api.py                 # 漫画网络出口设置与目标域探测 API
│   ├── mobile_entry.py            # Chaquopy 本机回环服务、私有目录和移动生命周期
│   ├── runtime.py                 # 显式启停控制器
│   ├── capabilities.py            # 运行依赖判定，不代替逐源实测
│   ├── manga_catalog.py           # 移动漫画源目录和验证状态
│   └── novel_catalog.py           # 小说源移动目录
├── engine/
│   ├── crawler.py / rules.py      # legado 规则解析、目录/正文分页
│   ├── cleaner.py                 # 正文净化、重复块和段落结构修复
│   ├── fetcher.py                 # 小说规则书源请求和代理池路径
│   ├── netproxy.py                # 漫画通道显式代理和会话重置
│   ├── manga/                     # 漫画适配器、图片处理、下载和缓存
│   └── adapters/                  # 小说专属适配器
├── android/                       # Compose、前台服务、私有存储、回环网关和 APK 构建
├── templates/ static/             # 桌面 Web，不是 Android 主流程的替代实现
├── sources/                       # 用户/桌面书源运行数据
├── data/                          # 书库、缓存、代理和健康状态运行数据
├── tests/                         # Python、Node、Android 契约与回归测试
└── tools/                         # 真实网络探针和人工验收工具
```

### 不可跨越的边界

1. **桌面与 Android 分开运行。** 可以共享 Python 业务代码和 API 契约；Android 核心搜索、详情、阅读、书架和下载不应回退到桌面 WebView/HTML。
2. **`sources/` 与 `data/` 是用户运行数据。** 书源、书库、缓存、`proxy_good.txt`、健康记录和下载状态不得被无关修复覆盖、清空或纳入提交。
3. **代码通过不等于源站可用。** `HTTP 200`、服务 `ready`、构建成功、依赖可导入均不能替代真实搜索、目录、正文/图片、下载、离线阅读和恢复验证。
4. **代理只是一条可选网络出口。** 手机默认直连即可独立运行；不能把代理描述为电脑、云端后端或绕过站点限制的方案。
5. **当前运行服务尚未加载本轮工作树修复。** 受控发布并通过健康检查前，不得把本轮正文修复描述为已上线。

## 2. 已落地的关键纠偏

### 2.1 R78：恢复、进度和离线归因

- “恢复最近一次清理”只恢复最近一个仍含 JSON 的批次；显式批次优先；同名用户书源不覆盖。
- 小说和漫画阅读器都要求返回、手势返回、切后台/锁屏时保存进度。
- 小说阻塞搜索在无网络时需要明确归因为网络不可用，不能显示成“无结果”。

**尚未闭环：** 小说退出保存当前由源码不变式测试锁定；仍需在目标 Android 设备验证返回、手势、切后台、锁屏和进程恢复后的真实落盘。

### 2.2 R79：正文完整性、净化与分页

- 规则中的 `@正则:` 选择器在带标签场景回退到 HTML 标记文本，避免规则匹配不到导致多页章节只取第一页。
- 正文分页会检测重复整页、链接回环、预算耗尽和中途错误；未取完且仍有下一页时，应报告失败而不是静默交付残章。
- 正文净化根据真实书库离线普查补充特定广告/残留规则；这些结果是**已下载正文的离线证据**，不是手机真机或实时外站验证。
- 整块去重的实际判据是：连续至少 3 行、每行至少 10 字、整块至少 200 字、逐字节相同；仅删除后出现的重复块。
- 墙体章节只对长度至少 1500 字的单行按句末标点拆段；普通行、空行和既有换行必须保留。

### 2.3 本轮追加修复：混合章节段落结构

此前墙体行修复在章节内任一行被拆段时，会以双换行重新拼整章，导致普通行和原有空行也被重排。现已改为：

- 仅在墙体行内部插入新的段落换行；
- 非墙体行和既有空行按原样保留；
- 墙体行去掉新增换行后仍逐字节等于原行；
- 新增“普通段落 + 墙体行 + 普通段落”的混合章节回归。

这项修复只在工作树和离线测试中通过，尚未重启桌面服务或构建 APK。

## 3. 当前 P0 / P1 工作顺序

### P0-1：受控发布当前正文修复

1. 检查 `git diff --check`、正文/分页定向回归和服务启动环境。
2. 仅发布代码文件；不带入 `sources/`、`data/`、缓存、日志和代理记录。
3. 原子重启桌面服务，检查健康端点、监听 PID 和运行时日志。
4. 选取已知墙体章节和混合章节验证：普通段落间距未被改写、墙体行可读、字符未丢失。
5. 失败则回滚本轮代码改动，不触碰用户数据。

### P0-2：小说分页完整性闭环

每个准备标记为可用的小说源应至少验证：

```text
搜索 → 详情 → 全目录 → 多页正文 → 正文末尾 → 缓存重读 → 退出恢复
```

必须记录源 UID、书名/章节标识、网络条件、页数、章节数、失败阶段和测试时间。分页失败、下一页循环、预算耗尽、正文截断都不能被归为“正常空内容”。

### P0-3：Android 小说进度行为验证

针对 release APK 的目标设备验证：

```text
进入小说中段 → 滚动 → 顶栏返回 → 再进入
进入小说中段 → 系统返回/手势返回 → 再进入
进入小说中段 → 切后台/锁屏 → 回到应用
进入小说中段 → 停止/重启本机引擎 → 再进入
```

每项都应恢复到相同章节和合理页码；失败时记录请求、返回码和进度 payload，不记录用户隐私或凭据。

### P1-1：文档口径收敛

- README 中的历史“77 个全部可用”“21 启用/10 禁用”等数量不能作为当前可用性声明。
- 当前指南是唯一执行基线；旧阶段、旧版本和历史评审文件只能作为历史证据。
- 版本、`versionCode`、Git revision、构建时间、签名和 APK SHA-256 必须在发布清单中对应同一个产物。

### P1-2：源验证与网络出口

- 漫画代理和小说规则书源代理是两套实现，需分别展示和测试。
- 真实网络探针必须在隔离 `WR_DATA_DIR` 下运行；它们会访问源站，适配器/代理池可能产生本地状态。
- 未经目标手机实测的源只能标记为待验证、降级或条件可用，不能标记为 Android 已验证。
