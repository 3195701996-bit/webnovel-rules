# 仓库维护约定

[文档导航](README.md)

## 分支与版本

- `main` 是项目入口，跟进已验证的稳定源码与维护文档。
- 日常改动放在短生命周期分支，经 PR 和 CI 合入；不把开发分支直接当作公开稳定下载。
- Release 标签固定到准确构建提交。后续文档整理不移动标签，不替换已发布 APK，也不为了“目录干净”删除历史版本。
- 本次同步保留已有分支与候选 Release；后续删除旧分支或资产须明确列出范围并确认。

## 文档层级

- README：介绍、下载、真实截图、快速开始和导航。
- 当前指南：`docs/README.md`、架构、开发与维护约定。
- 版本说明：由版本索引导航；保留既有文件路径。
- 历史评审/调研：标注历史身份，保留证据，不把当时待办写成当前故障。

新文档尽量使用明确主题名，避免新的“当前版本”“最终版”文件。更改路径时检查仓库内引用；已经公开使用的路径优先保留。

## 截图与运行数据

- 首页截图来自实际运行的 App/Web；标注版本、客户端和演示数据范围。
- 设计概念图不混入实际截图。禁止公开真实用户书库、阅读历史、凭据、代理和设备标识。
- `data/`、构建产物、签名材料、环境变量和机器配置不入库；添加忽略规则不删除磁盘文件。
- 问题附件先脱敏，尤其是诊断报告、连接记录和屏幕截图。

## 工具与许可

当前构建和测试命令以 [开发指南](development.md) 及 CI 为准。旧脚本的兼容入口只能转发到现有流程，不能继续向废弃目录同步副本。

不要在整理时自行增加许可证或修改第三方文件的许可声明；仓库授权方案由维护者单独确认。第三方研究副本保留来源说明，不能当作运行依赖清单。
