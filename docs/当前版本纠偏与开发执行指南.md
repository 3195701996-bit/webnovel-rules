## 1. 当前结构与边界

```text
webnovel_rules/
├── app.py                         # 桌面 Flask 组合根、桌面页面路由与蓝图装配
├── server/
│   ├── novel_api.py               # 小说搜索、目录、正文、书库与进度 API
│   ├── manga_api.py               # 漫画搜索、详情、阅读、图片、下载、历史 API
│   ├── net_api.py                 # 本机代理设置与目标域连通性探测 API
│   ├── mobile_entry.py            # Chaquopy 运行入口：私有目录、回环服务、移动生命周期
│   ├── runtime.py                 # 显式运行时启停
│   ├── capabilities.py            # 依赖能力判定，不代替功能验证
│   ├── manga_catalog.py           # 漫画源目录、移动可用性与验证状态
│   └── novel_catalog.py           # 小说源移动目录
├── engine/
│   ├── manga/                     # 漫画适配器、图片处理、下载、会话与缓存
│   ├── adapters/                  # 小说专属适配器
│   ├── fetcher.py                 # 小说规则引擎的 HTTP/代理池路径
│   ├── netproxy.py                # 漫画通道的显式代理设置和会话重置
│   └── crawler.py / rules.py      # legado 规则书源解析链路
├── templates/ static/             # 桌面 Web UI；不是 Android 核心 UI 的替代品
├── android/                       # Compose UI、前台服务、回环网关、私有存储、APK 构建
├── sources/                       # 用户/桌面书源运行数据，不是代码修复目标
├── data/                          # 书库、缓存、运行状态和网络状态，不是代码修复目标
├── tests/                         # Python/Node 离线契约与回归测试
└── tools/                         # 真实网络探针；运行前必须阅读各工具的副作用边界
```

### 不可跨越的边界

1. **桌面与 Android 是两个运行环境。** 可共享 Python 业务代码和 API 契约，但 Android 核心流程不得回退到桌面 HTML/WebView。
2. **`sources/`、`data/`、`data/proxy_good.txt` 是运行态内容。** 未经明确需求不得覆盖、重置、格式化、清空或纳入无关修复。
3. **本快照中 `engine/manga/copymanga.py`、`engine/manga/copy_web.py`、`tests/test_copy_web_channel.py` 属另一条未提交的网页通道开发线。** 它们必须和本指南的续读/代理纠偏分开测试、审查和提交，不能借本次回归测试宣称网页通道已验证。
4. **服务 `ready`、构建成功、HTTP 200、依赖存在，都不是源站可用证明。** 必须区分离线代码契约、桌面真实网络、目标手机真实网络三类证据。
5. **代理是可选网络出口，不是电脑或云后端。** 手机默认直连即可独立运行；代理只在用户自己已有可用网络出口时改善部分目标域可达性。

## 2. 当前已确认的纠偏状态

### 2.1 漫画继续阅读入口已统一为 `resume`

阅读器把 URL 中的 `ch` 当作“用户明确选章”；无 `ch` 时才读取服务端 `resume`。因此“继续阅读”入口不得伪造 `ch=0` 或旧目录下标。

当前应遵守：

| 入口 | 行为 |
|---|---|
| 书库漫画卡片 | 不传 `ch`，按服务端 `chapter_id`/章节名/话号恢复 |
| 漫画历史卡片 | 不传旧 `idx`，按服务端章节身份恢复 |
| 任务页漫画标题 | 不传 `ch`，与书库语义一致 |
| 详情页/目录中用户点某一话 | 传 `ch`，明确选章优先于恢复位置 |

本轮已补齐任务页残留的 `ch=0` 强制入口及离线回归。旧记录若已经被此前缺陷写成第一话，系统不能凭空推回第 20 话：用户手动选择一次正确章节并退出后，后续继续阅读应按新身份记录恢复。

### 2.2 漫画图片处理与旧缓存

JM 图片还原已使用处理版本标记。带处理版本的章节缓存只有与当前算法一致时才可直接读取；旧版本缓存应按章节选择性失效后重取，不能要求用户清空书架或整个应用数据。

仍须在目标手机验证：新图、多页阅读、旧缓存重建、下载、断网阅读和应用重启后的结果。离线测试不能证明任何真实源站在任意网络下可用。

### 2.3 分源漫画搜索

服务端、原生搜索状态和单源入口必须始终保持同一组：`source`、`keyword`、`order`、页码与结果代际。以下行为一律视为回归：

- 单源搜索静默变成全源搜索；
- 首搜、流式回退、翻页中任一路丢失 `source`；
- 返回页面后清除关键词、源、排序、页码或滚动位置；
- 未验证/不支持源仍被默认搜索。

### 2.4 代理与网络路径：两条链路必须分开说明

| 范围 | 当前优先级 | 持久化/副作用 | 维护规则 |
|---|---|---|---|
| 漫画 API、JM、图片、拷贝 APP 通道 | `WR_PROXY` → `WR_PROXY_FILE` → 直连 | Android 的文件位于应用私有 `runtime_config/proxy.txt`；修改后重置漫画通道会话 | 由 `engine/netproxy.py` 与 `server/net_api.py` 管理 |
| 小说规则书源抓取 | 书源 `proxy` → `WR_PROXY` → 代理池 | 代理池可能读取/更新 `data/proxies.txt`、`data/proxy_good.txt` | 由 `engine/fetcher.py` 管理；不能误说成与漫画设置完全同一实现 |

不允许为了“所有源直连成功”强制启用代理、默认写入公共代理或将代理配置暴露给远程客户端。代理 API 的写操作默认仅允许本机回环来源；远程配置必须显式打开受控开关并评估风险。

### 2.5 传输能力与 Android 支持口径

`curl_cffi` 缺失不再自动等价于“拷贝漫画 Android 不支持”。当前实现允许部分源走 `requests` 降级路径；但是否可用取决于目标域可达性、源站业务限制和真实图片通道结果。

以下能力不得被写为 Android 已验证：

- Playwright/桌面 Chrome 网页渲染通道；
- 只有依赖探测而没有搜索、详情、图片和阅读实测的源；
- 源码文件存在但未注册、未进入移动源目录的适配器；
- 仅在桌面代理下成功、未在目标手机网络验证的源。

## 3. 真正的 P0 / P1 工作顺序

### P0-1：目标手机漫画闭环

逐源执行并记录：

```text
原生单源搜索
→ 详情/目录
→ 首图
→ 多页连续阅读
→ 下载一话
→ 断网打开已下载章节
→ 停止/重启引擎后恢复阅读
```

记录：APK SHA-256、版本、Git revision、设备/Android 版本、网络类型、是否设置代理、源 key、失败阶段、受控错误码、时间。不得记录 Cookie、登录信息、完整签名参数或代理凭据。

### P0-2：真实网络探针的隔离和证据

下列工具都会访问真实外站，不能当作普通离线测试：

- `tools/probe_source_transport.py`：真实调用漫画源搜索、详情、图片；部分适配器可能写本地状态。
- `tools/novel_regression_live.py`：真实执行小说搜索、目录与正文读取；运行前必须设置临时 `WR_DATA_DIR`，避免代理池或缓存意外写入用户数据。

推荐执行形式：

```bash
WR_DATA_DIR=/tmp/wr-novel-regress \
  ./venv/bin/python tools/novel_regression_live.py
```

每次探针结论必须注明网络、代理、时间、源站响应和是否运行在设备上。桌面探针只证明桌面当时的网络路径，不能替代 Android 验收。

### P0-3：续读全入口防回归

每次改动书库、任务、历史、详情或阅读器 URL 时，必须验证：

1. 继续阅读链接不含 `ch`/`idx`/章节参数；
2. 目录显式选章仍含章节参数；
3. 服务端 `resume` 保留 `chapter_id`、章节名、页号；
4. 阅读器在恢复尚未精确匹配时不把第一话写回历史；
5. 书库刷新签名包含阅读状态字段。

### P1-1：小说最小回归集

网络、缓存、规则、代理、正文净化或移动快照改变时，执行具名小说源的搜索 → 目录 → 首章正文回归。失败要区分：源站连接、结果选择、目录、正文、规则解析、网络路径；不能全部归为“网络问题”。

### P1-2：文档和构建身份

发布候选必须展示并记录：版本、`versionCode`、Git revision、构建时间、签名信息和 APK SHA-256。README、应用内诊断、发布说明和本文件必须使用同一版本基线；不要引用已删除或不在仓库中的旧指导文件。

这组证明 URL 入口语义、阅读身份、图片处理、搜索参数和代理 API 的代码契约；不访问外站。

### 桌面真实网络（显式、隔离地执行）

- 先设置临时 `WR_DATA_DIR`；
- 只运行明确指定的最小源/最小漫画源；
- 记录网络/代理和失败阶段；
- 结果不能自动写进“Android 已验证”。

### Android 真机（发布前）

- 运行 release 构建对应的 instrumentation；
- 按 P0-1 逐源闭环；
- 验证首次启动、内置源解出、默认直连、可选代理保存/清除、前台服务中断原因、存储不足、恢复、导入导出；
- 确认核心流程没有 WebView 回退。

## 5. 停止项

- 不再以桌面 HTML/WebView 作为 Android 搜索、阅读、书架或下载的默认入口。
- 不再用 `HTTP 200`、服务 ready、依赖可导入或构建成功替代真实业务验收。
- 不再把 Playwright 或桌面 Chrome 作为 Android 功能承诺。
- 不再为修图片、续读或源状态而清空 `data/`、用户书架或全部图片库。
- 不再把真实外网探针标成“无副作用离线测试”。
- 不再用代理掩盖源站限制或规避站点技术保护；代理只改变用户已有的网络路径。
- 不修改未提交的书源、代理记录或 Android 并行开发文件来完成无关修复。
